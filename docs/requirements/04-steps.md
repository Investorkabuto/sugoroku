# 04 歩数（HealthKit）

状態：下書き

## 方針

**歩数は何も操作しなくても自動で届き、本人の普段と比べてほめる。**
他の人と比べたり、目標に届かないことを責めたりしない（P-02-02、P-02-03）。
歩数は「ヘルスケア」アプリから読むだけで、アプリから書き込みはしない。
iOSだけの処理（HealthKit）は services 層に閉じ込め、Android では後から Health Connect に置き換える（R-01-05）。

## 言葉の決まり

| 言葉 | 意味 |
|---|---|
| 歩数の日 | 歩数を数える1日。0:00〜24:00（端末の時間帯）。「ヘルスケア」アプリの表示と同じにする |
| 普段の歩数 | 本人の過去14日（仮）の歩数の中央値。ほめる基準に使う |
| 歩数のごほうび | 歩数で届く旅ポイント（R-02-06）。「基本」と「上乗せ」の2つ |

## 歩数の読み取り

| 番号 | 要件 |
|---|---|
| R-04-01 | 「ヘルスケア」の歩数（stepCount）を読み取る。読み取る項目は歩数だけにする |
| R-04-02 | 1日の歩数は、iPhone と Apple Watch の重なりを除いた合計を使う（「ヘルスケア」の合計と同じ値。HealthKit の集計の問い合わせを使う） |
| R-04-03 | 手入力された歩数（「ヘルスケア」アプリで利用者が追加したもの）は、ごほうびの計算に含めない。画面の表示にも含めない |
| R-04-04 | Apple Watch は必要としない。iPhone だけで歩数が取れる |
| R-04-05 | 歩数を読むのは次のとき：アプリを開いたとき、HealthKit の裏での配信（Background Delivery。1時間ごと、仮）、iOS の裏での更新（Background App Refresh）、服薬の通知のボタンが押されたとき |
| R-04-06 | iPhone がロックされている間は「ヘルスケア」のデータを読めない（iOS の仕様）。読めなかったときは、次に読める機会で読み直す |
| R-04-07 | 過去2日分（仮）は毎回読み直す。Apple Watch の歩数が遅れて届いても反映されるようにする（R-03-43 と同じ期間） |

## 歩数の日と1日の区切り

| 番号 | 要件 |
|---|---|
| R-04-10 | 歩数は 0:00〜24:00 で数える。服薬の1日の区切り（午前3時、R-02-15）とは別にし、「ヘルスケア」アプリと数字が合うようにする |
| R-04-11 | ある日の歩数のごほうびは、その日の翌日の午前3時（R-02-15）以降に確定する。確定前も、届く見込みを画面に出してよい |
| R-04-12 | 旅行で時間帯が変わった日も、端末の時間帯で数える（R-03-30 と同じ） |

## 普段の歩数

| 番号 | 要件 |
|---|---|
| R-04-20 | 普段の歩数 ＝ 前日までの14日（仮）のうち、歩数が取れた日の中央値。平均ではなく中央値にし、旅行などで多く歩いた日に引っぱられないようにする |
| R-04-21 | 歩数が0の日、データがない日は、普段の歩数の計算から外す（スマホを持たずに過ごした日で基準が下がりすぎないように） |
| R-04-22 | 歩数が取れた日が7日（仮）に満たない間は、仮の基準（3,000歩、仮）を使う。始めたばかりの人もごほうびを受け取れるようにする |
| R-04-23 | 普段の歩数には下限（1,000歩、仮）を設ける。基準が低くなりすぎて、ほとんど歩かなくても上乗せが届く状態を防ぐ |
| R-04-24 | 普段の歩数は本人の画面に表示する。数字の意味（「最近2週間のふつうの日」）を一言で添える |
| R-04-25 | 決まった目標歩数（例：1日8,000歩）は設けない。体の状態に合わせて、本人の普段を基準にする |

## 歩数のごほうび

02 の旅ポイント（R-02-06〜R-02-13）のうち、歩数で届く分を決める。量と値段は試作で決める（Q-02-04）。

| 番号 | 要件 |
|---|---|
| R-04-30 | **基本**：その日の歩数が普段の歩数の半分（仮）以上なら、基本の旅ポイントを付ける |
| R-04-31 | **上乗せ**：その日の歩数が普段の歩数を上回ったら、旅ポイントを上乗せする（R-02-12） |
| R-04-32 | 上乗せは1段階だけにし、1日に届く量に上限を設ける。多く歩くほど増え続ける形にはしない（無理な運動を勧めないため） |
| R-04-33 | 薬を登録している人は、服薬の達成率（R-03-50）のごほうびに、歩数の基本と上乗せを足す。歩数は服薬の達成率には混ぜない |
| R-04-34 | 薬を登録していない人（家族、服薬予定がない日の本人）は、歩数の基本と上乗せだけで旅ポイントが届く（Q-02-03、R-03-53） |
| R-04-35 | 歩数を読めない人（許可していない、iPhone を持ち歩かない）は、歩数のごほうびがないだけで、他のことで不利にならない |
| R-04-36 | 歩数が後から増えた場合（R-04-07）、ごほうびは増える方向にだけ直す。いったん届いた旅ポイントは取り消さない（P-02-03） |
| R-04-37 | 旅ポイントの付与はサーバーで判定する（R-02-17）。端末は1日ごとの歩数の合計を送り、サーバーがその日の確定（R-04-11）と普段の歩数を計算する |
| R-04-38 | ありえない値（1日10万歩を超えるなど、仮）は、ごほうびの計算に使わない |

## 許可の求め方

| 番号 | 要件 |
|---|---|
| R-04-40 | 歩数の許可は、初回の案内の最後か、歩数の画面を初めて開いたときに求める。許可を求める前に、何に使うか（旅ポイントのため、家族に歩数そのものは見せない）を1画面で説明する |
| R-04-41 | 許可しなくてもアプリは使える。後から設定で許可できることを伝える |
| R-04-42 | iOS は「読み取りを許可したか」をアプリに教えない（拒否されても、データがないように見える）。そのため、3日（仮）続けて歩数が0のときは、「歩数が届いていません」と表示し、「ヘルスケア」アプリの設定の開き方を案内する |
| R-04-43 | R-04-42 の案内はアプリ内の表示だけにし、通知はしない。閉じたら7日（仮）は出さない |

## 表示

| 番号 | 要件 |
|---|---|
| R-04-50 | 最初の画面に今日の歩数と、普段の歩数との比べ方（「いつもより多い」など）を出す |
| R-04-51 | 7日分の歩数を棒グラフで見られる。普段の歩数を線で重ねる |
| R-04-52 | 普段より少ない日も責める言葉を出さない。数字だけを表示する |

## 家族との共有

| 番号 | 要件 |
|---|---|
| R-04-60 | 家族に歩数を見せるかは本人が決める（R-10-11 の共有範囲）。初期状態では見せない |
| R-04-61 | 共有する場合も、見せるのは「今日歩いたかどうか」か「その日の歩数」までにする。時間ごとの歩数は見せない |
| R-04-62 | MVPでは、歩数を見守りの通知（R-10-12）の条件に使わない。見守りは服薬の記録で判定する |

## 保存とプライバシー

| 番号 | 要件 |
|---|---|
| R-04-70 | サーバーへ送るのは1日ごとの歩数の合計だけにする。時刻ごとのデータ、位置、心拍などは送らない |
| R-04-71 | 歩数をサーバーへ保存する前に、本人の同意を取る（08）。同意しない場合、歩数は端末内の表示だけに使い、歩数のごほうびは付かない |
| R-04-72 | HealthKit から読んだデータは、広告、外部の事業者、iCloud への保存に使わない（App Store 審査ガイドライン 5.1.3、R-11-03） |
| R-04-73 | アカウントを削除すると、サーバーの歩数を削除する（R-08-22）。「ヘルスケア」アプリの歩数そのものは消さない（Apple のデータのため） |
| R-04-74 | 「ヘルスケア」の利用目的の説明文（Info.plist の NSHealthShareUsageDescription）とプライバシーポリシーに、歩数の使い道を書く |

## 決まったこと

- 歩数は「ヘルスケア」から読むだけで、書き込まない（2026-10-16、下書き）
- ほめる基準は決まった目標歩数ではなく、本人の普段の歩数にする（2026-10-16、下書き）
