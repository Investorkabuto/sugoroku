# 10 家族と交流

状態：下書き

## 方針

**家族は一緒に遊べる。でも、遊ばなくても見守れる。**
見守りは「一緒に旅をしている中で、自然に様子が分かる」形を目指し、監視されている感じを与えない。
家族の招待を、利用者を増やす主な入り口にする。

## 家族の役割

| 役割 | できること |
|---|---|
| 本人 | 健康の記録、旅、共有範囲の設定 |
| 一緒に旅する家族 | 自分の駒で同じ地図を旅する。自分の歩数で記録のごほうびが届く。応援、見守り |
| 応援する家族 | 駒を持たない。応援スタンプを送る、見守る |

1つの家族グループの中に、本人が複数いてもよい（例：父と母の両方が服薬中）。

## 要件

### 家族グループと招待

| 番号 | 要件 |
|---|---|
| R-10-01 | 家族グループを作った人が、招待リンクを LINE・メッセージ・メールで送れる |
| R-10-02 | 招待リンクからアプリを入れると、そのまま家族グループに参加できる（入れたあと、もう一度リンクを開く必要がない形を目指す） |
| R-10-03 | 高齢の方が自分で招待を受けられない場合に備え、家族が本人の端末で設定を代わりに進められる |
| R-10-04 | 家族グループの人数の上限は10人（仮） |
| R-10-05 | 家族グループから抜ける、メンバーを外す操作ができる |

### 見守り

| 番号 | 要件 |
|---|---|
| R-10-10 | 見守りの判定には「記録があるか」を使い、「アプリを開いたか」は使わない（P-02-01） |
| R-10-11 | 家族に見せる範囲は本人が決める。初期状態は「記録できているかどうか」だけを見せ、薬の名前は見せない |
| R-10-12 | 服薬の未記録が続いたとき（初期値：24時間、仮）に、見守る家族へ通知する。判定はサーバーで行う |
| R-10-13 | 本人の端末で通知の許可がオフになったことを検知し、本人と家族に知らせる |
| R-10-14 | 家族への通知は良い知らせ（地域をクリアした、など）を中心にし、異変の通知の文面は柔らかくする。通知の条件は家族側で調整できる |
| R-10-15 | 本人は、いつでも見守りを一時停止できる。停止したことは家族に伝わる |

### 家族の旅

| 番号 | 要件 |
|---|---|
| R-10-20 | 家族グループで1つの地図を共有し、一人ひとりが自分の駒を持つ |
| R-10-21 | 他の家族の駒の位置と、集めたスタンプが見える。健康の記録の中身は見えない（見守りの共有範囲とは別） |
| R-10-22 | 順位を付けない。協力して達成する目標を用意する（例：家族全員で進んだマスの合計で季節のイベントをクリア） |
| R-10-23 | 家族が本人に、記録のごほうびを1日1つまでおすそわけできる（形は 02 のサイコロの案で決める） |
| R-10-24 | 同じ名所に家族が集まると、一緒にスタンプがもらえる（待ち合わせ） |

### 応援

| 番号 | 要件 |
|---|---|
| R-10-30 | 定型の応援スタンプを送れる。自由な文章のやり取りは当面入れない |
| R-10-31 | 応援スタンプの通知は、受け取る人が初期状態でオンにするか選べる（P-02-05 の例外として、本人の同意で有効にする） |
| R-10-32 | 短い音声メッセージは第2段階（通報・削除の仕組みとあわせて入れる） |

## 安全とプライバシー

- 家族グループの外の人とはつながれない（なかまとの交流は将来、別に検討する）
- 健康の記録は要配慮個人情報。サーバーに保存する前に、本人の同意を取る（詳細は 08）
- サーバー側のアクセス制御（Firestoreのセキュリティルール）で、共有範囲の外のデータは読めないようにする
- アカウント削除をアプリ内でできるようにする（App Storeの要件）
