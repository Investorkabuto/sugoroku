# 03 服薬スケジュールと通知

状態：下書き

## 方針

**通知のボタン1つで記録が終わり、アプリを開かなくても、通信できなくても記録が残る。**
アプリは薬局・医師の指示どおりの時刻に知らせるだけで、飲み方を判断しない（08）。
健康の流れとゲームの流れは切り離す（P-02-01）。

## 言葉の決まり

| 言葉 | 意味 |
|---|---|
| 薬 | 利用者が登録した1つの薬（例：血圧の薬） |
| 服薬時刻 | 1日の中で薬を飲む時刻のまとまり（例：朝 8:00）。同じ時刻の薬は1つにまとめて扱う |
| 服薬予定 | ある日のある服薬時刻（例：10/16 の朝）。記録と達成率はこの単位で数える |
| 頓服 | 決まった時刻がなく、必要なときに飲む薬（例：痛み止め） |

## 薬とスケジュールの登録

| 番号 | 要件 |
|---|---|
| R-03-01 | 薬は手入力で登録する。入力するのは薬の名前だけで、ほかは省略できる |
| R-03-02 | 登録できる項目：名前、1回の量（例：1錠）、服薬時刻、飲む日、開始日、終了日、メモ（例：食後） |
| R-03-03 | 服薬時刻は「朝・昼・夕・寝る前」から選ぶ。それぞれの時刻は利用者が変えられる（初期値：8:00・12:00・18:00・21:00、仮） |
| R-03-04 | 飲む日は「毎日」「曜日を指定」「◯日おき」から選ぶ |
| R-03-05 | 終了日を入れると、その日の後は通知しない（処方の日数分だけ飲む薬のため） |
| R-03-06 | 頓服として登録した薬は通知せず、飲んだときにアプリから記録する。達成率には数えない |
| R-03-07 | 薬を一時停止・再開・削除できる。削除しても過去の記録は残す |
| R-03-08 | スケジュールを変えたときは、次の服薬予定から新しい内容を使う。過去の服薬予定と記録は変えない |
| R-03-09 | MVPでは、薬の登録と変更は本人の端末で行う。家族が本人の端末で代わりに入力してもよい（R-10-03） |
| R-03-10 | 量や飲み合わせの注意など、薬の内容についての判断はしない。メモは利用者が書いたとおりに表示する |

## 通知

| 番号 | 要件 |
|---|---|
| R-03-20 | 服薬時刻ごとに1件の通知を出す。同じ時刻の薬はまとめて1件にする |
| R-03-21 | 通知には「飲んだ」「あとで」の2つのボタンを付ける。ロックを解除しなくても押せる |
| R-03-22 | 「飲んだ」を押すと、その服薬予定の薬をすべて飲んだと記録する。アプリは開かない |
| R-03-23 | 「あとで」を押すと、15分後（仮）にもう一度通知する。回数の制限はなく、1日の区切り（R-02-15）まで使える |
| R-03-24 | ボタンを押さずに通知を閉じた場合、30分後（仮）に1回だけ知らせ直す。その前に記録すれば知らせ直さない |
| R-03-25 | ロック画面の通知に、初期状態では薬の名前を出さない（例：「朝のお薬の時間です（2種類）」）。本人が設定で名前を出すようにできる |
| R-03-26 | 通知は「時間確定（Time Sensitive）」として出し、集中モード中でも届くようにする。消音モードでも鳴る「重要な通知」は使わない（01） |
| R-03-27 | 通知の許可は、最初の薬を登録した後に求める。許可を求める前に、なぜ必要かを1画面で説明する |
| R-03-28 | 通知の許可がオフのときは、アプリの最初の画面に分かりやすく表示し、設定を開くボタンを置く。本人と家族への知らせは R-10-13 |
| R-03-29 | ゲームと交流の通知とは別の種類にし、服薬の通知だけをオンにしておける（P-02-05） |
| R-03-30 | 通知の時刻は端末の時刻と時間帯に合わせる。旅行で時間帯が変わったら、その土地の時刻で知らせる |

### 予約できる通知の上限への対応

iOSで予約できる通知は1つのアプリにつき64件まで。そのため、近い日の分から予約し、少なくなったら補充する。

| 番号 | 要件 |
|---|---|
| R-03-35 | 服薬の通知と知らせ直し（R-03-24）を、近い順に最大60件（仮）まで予約する。残りの枠は「あとで」などに使う |
| R-03-36 | 次のときに予約を補充する：アプリを開いたとき、通知のボタンが押されたとき、iOSの裏での更新（Background App Refresh）のとき、サーバーからの補充用の通知（FCMの通知を出さないメッセージ）を受けたとき |
| R-03-37 | 予約がなくなる2日前（仮）になっても補充できていない場合、最後の通知に「アプリを一度開いてください」と添える |
| R-03-38 | スケジュールを変えたとき、薬を止めたとき、記録したときは、関係する予約を取り消して入れ直す |

## 記録

| 番号 | 要件 |
|---|---|
| R-03-40 | 服薬予定ごとの記録は「飲んだ」「スキップ」「飲み忘れ」「未記録」の4つ |
| R-03-41 | 「スキップ」は医師の指示などで意図して飲まなかったとき、「飲み忘れ」は後から飲めなかったと記録するときに使う。どちらも記録として数える（P-02-04） |
| R-03-42 | まとめて記録したあと、アプリで薬ごとに直せる（例：3種類のうち1つだけ飲まなかった） |
| R-03-43 | 過去の服薬予定も2日前（仮）まで記録・修正できる。それより前は表示だけにする |
| R-03-44 | 1日の区切り（R-02-15）を過ぎても未記録の服薬予定は「未記録」のままにする。自動で「飲み忘れ」にはしない |
| R-03-45 | 記録の時刻は、ボタンを押した時刻を残す。通知の時刻からずれていても、同じ服薬予定の記録として扱う |
| R-03-46 | 頓服は、薬と時刻を選んで「飲んだ」を記録する |
| R-03-47 | 記録の一覧（カレンダー）を本人が見られる。通院のときに見せられるよう、文字を大きくできる |

## 達成率

02 のごほうびの量（R-02-11）と、10 の見守りの判定（R-10-10）に使う。

| 番号 | 要件 |
|---|---|
| R-03-50 | 1日の達成率 ＝ 記録した服薬予定の数 ÷ その日の服薬予定の数。薬の数ではなく服薬時刻で数えるため、薬が多い人も少ない人も同じ条件になる（R-02-11） |
| R-03-51 | 「飲んだ」「スキップ」「飲み忘れ」は記録として数え、「未記録」は数えない |
| R-03-52 | 家族に見せる「記録できているか」（R-10-11）は、この達成率をもとにする。「飲んだ」かどうかを見せるかは、本人が共有範囲で決める |
| R-03-53 | 服薬予定がない日（薬を登録していない人を含む）の扱いは 04 で決める（Q-02-03） |

## 端末内の保存と同期

| 番号 | 要件 |
|---|---|
| R-03-60 | 薬、スケジュール、記録はまず端末内に保存する。通知の予約と記録は、通信がなくても動く（R-01-07） |
| R-03-61 | 通信できるようになったら、まだ送っていない記録をサーバーへ送る。記録の時刻は端末で押した時刻を使う |
| R-03-62 | 同じ服薬予定の記録が複数の端末から届いた場合は、後から押した記録を正とする |
| R-03-63 | 見守りの「未記録が続いた」判定（R-10-12）では、端末が最後にサーバーとつながった時刻もあわせて見る。つながっていないだけなのか、記録がないのかを家族への知らせで区別する |
| R-03-64 | 薬の名前とメモは、端末を替えたときに引き継ぐためにサーバーへ保存する。保存の前に本人の同意を取る（10 の安全とプライバシー、08） |

## 決まったこと

- 通知は服薬時刻ごとにまとめ、ボタン1つで記録できる形にする（2026-10-16、下書き）
